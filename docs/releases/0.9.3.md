A warning when the dashboard's timezone is left at UTC, which puts the e-paper display's times
and the update schedule hours off.

## What's changed

- **A warning when `TZ` is unset or UTC.** `docker-compose.yml` ships with `TZ=Etc/UTC`, and
  it's easy to leave. Then updates run on UTC's clock (6am to 9pm UTC, not your 6am to 9pm), and
  the display's "Last change" time is in UTC, hours off. The web dashboard looks right either
  way, since it shows times in your browser's timezone. `docker compose logs` now says so at
  startup, with what to change.
- **The README's install steps** now include setting `TZ` in `docker-compose.yml`.

## Upgrading

If your `docker-compose.yml` still says `TZ=Etc/UTC` and you're not in UTC, change it to your
timezone, as a [tz database name](https://en.wikipedia.org/wiki/List_of_tz_database_time_zones)
such as `America/Chicago`. Then run `docker compose up -d`, which also picks up this release if
you have `pull_policy: always`; otherwise run `docker compose pull && docker compose up -d`.

To stay on this release, set the image line to:

```yaml
    image: afraley/skyward-dashboard:0.9.3
```

Nothing changes in the display firmware.
